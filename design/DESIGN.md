# Lore-Friendly — 디자인 분석 (DESIGN.md)

Figma 파일 `Lore-Friendly 초안.fig` 1개 페이지(Page-1), 17개 프레임을 분석한 결과입니다.
모든 수치·색상은 파일에서 그대로 추출한 값입니다(반올림·그리드 스냅 없음).

---

## 1. 제품 개요

**Lore-Friendly** — 2차 창작(팬픽) 집필 도구. 작가가 원고를 쓰면 AI가 ①작품 내부 모순과 ②원작(원전)과의 차이를 검출하고, 작가가 각 쟁점을 "수정 / 문제없음 / 보류 / 작품 설정으로 확정" 중 하나로 처리해 **작품 고유의 설정(canon)을 누적**해 가는 구조.

샘플 데이터는 MCU/Marvel 기반 팬픽(작품명 «푸른 큐브의 다른 가능성», 작가 서하윤)으로 채워져 있습니다.

핵심 개념 4가지:

| 개념 | 설명 |
|---|---|
| 참고 자료 (Reference) | 업로드한 원작 자료. 자료 간 불일치도 감지 |
| 기준 설정 (Baseline) | 원작 기준의 사실. 예: "코스믹 큐브는 공간 이동만 가능하다" |
| 쟁점 (Issue) | 원고 ↔ 기준 설정 충돌. 미해결 / 보류 / 해결됨 |
| 작품 설정 (Confirmed) | 작가가 "확정"한 변경. 기준 설정을 대체하고 이후 검증 기준이 됨 |

## 3. 레이아웃 시스템

전 화면 공통: **1440×900 고정, 세로 flex = 글로벌 내비(56px) + 본문(flex-grow)**

### 글로벌 내비게이션 바 (56px)
- 배경 `#FFFFFF`, 1px `#E2E8F0` 테두리, padding `0 24px`, space-between
- 좌: 로고(`Lore` Inter Bold Italic 16 `#4F46E5` + `Friendly` Regular 15 `#1E293B`, gap 2, baseline 정렬) → 구분선 → 작품 드롭다운(162×24, r6, bg `#F8FAFC`) → 브레드크럼(제3장 › 장면 2…)
- 우: "자동 저장됨" 12px `#94A3B8` → 세그먼트 탭 188×32 (r8, bg `#F8FAFC`, padding 2, gap 2) → 내보내기 버튼 80×28 (r8, 흰 배경 + 1px 보더)
- 탭 3개: **집필 / 검토 / 자료실**

### 본문 컬럼 폭 — **통일 규격 (확정)**

좌 **280** / 우 **320** 으로 통일합니다. 중앙은 항상 `flex: 1`.

| 화면 | 좌 패널 | 중앙 | 우 패널 |
|---|---|---|---|
| writing-editor | **280** | flex, 시트 720 | **320** |
| review-* | **280** | flex, 시트 720 | **320** |
| library-* | **280** | flex | **320** |
| export-pdf-* | **380** (조판 설정, 그대로 유지) | flex (미리보기 워크스페이스) | — |
| library-basic-settings | — | 단일 중앙 카드 (패널 없음) | — |
| writing-focus | — | 시트 680 | — |

원본 파일 값(참고): writing-editor 260/290, review 280/360, library 280/320, export 사이드바 380.
→ 세 패널 구조 화면만 통일 대상입니다. **export 사이드바 380은 예외** — 조판 폼(라벨 + 컨트롤 2열)이 들어가야 하고 우측 패널이 없어 성격이 다릅니다. `library-basic-settings`도 패널 없는 단일 카드 레이아웃이므로 제외.
다수인 280을 좌측 기준으로, 우측은 세 값의 중앙값이자 가장 많이 쓰인 320을 기준으로 채택. 1440 기준 중앙 영역은 840px(패딩 24 제외 시 792px)로, 720px 문서 시트를 여유 있게 수용합니다.

**우측 인스펙터 360 → 320 조정 검증 결과** (`Panel Width Check.dc.html`에서 원본 프레임을 실제 렌더링해 측정)

- 인스펙터 콘텐츠 폭: 312 → **272** (padding 24 유지). 타입 배지(96) + 상태 배지(47) + gap 8 = 151 → 배지 행 안전.
- 🔴 **깨짐 1건 — 근거 출처(source-card) 아코디언 헤더.** 출처 라벨이 `width: 260px` + `white-space: nowrap` 고정이라 chevron 12px와 합쳐 272px. 카드 내부 가용폭 248px를 **24px 초과**. 360폭(288px 가용)에서는 가려져 있던 문제.
  → 수정: 고정폭 제거 후 `flex: 1; min-width: 0; white-space: nowrap; overflow: hidden; text-overflow: ellipsis`. 적용 후 넘침 0건 확인.
- 🟡 **하단 보조 버튼 행이 정확히 한계치.** 설정으로 확정 158 + 문제없음 60 + 보류 38 + gap 16 = **272px** = 가용폭. 라벨이 한 글자만 길어져도 넘침.
  → 수정: 버튼 행 `flex-wrap: wrap`, 인스펙터 푸터 `height: 92` → `min-height: 92` (고정 높이를 유지하면 2행이 잘림). 라벨을 «작품 전체 설정으로 확정하기»로 늘려 검증 — 행 28 → 64px 2행, 푸터 134px까지 신축, 잘림 없음.
- 인용 카드·근거 출처 카드의 13px 본문은 줄 수만 늘어남 → 패널 스크롤로 흡수, 레이아웃 영향 없음.
- ✅ `writing-editor` 260/290 → 280/320 은 양쪽 모두 **확대** 방향 → 이상 없음.
- ✅ `library-*` 는 이미 280/320 → 변경 없음.
- ✅ 중앙 영역: 1440 − 280 − 320 − padding 48 = **792px** 가용 → 720px 문서 시트 여유 있게 수용.

패널 공통: 배경 `#FFFFFF`, `inset 0 0 0 1px #E2E8F0` (또는 1px border), padding 16~24, 세로 flex gap 16/20.
중앙 에디터 영역: 배경 `#F8FAFC`, padding 24, 가운데 정렬.

### 문서 시트
- review: 720px, `border-radius: 12px 12px 0 0`, `inset 0 0 0 1px #E2E8F0` + `0 1px 3px rgba(0,0,0,.03)`
- focus: 680px, r8, padding 60, `0 2px 8px rgba(0,0,0,.0196)`
- 시트 헤더 57px, 하단 푸터에 글자수/자동저장 표기
- 본문 타이포: 15px / `line-height: 2` / 문단 gap 24 / `#1E293B`

## 5. 타이포그래피

| 본문(원고) | Inter Regular | **15 / line-height 2** | 원고 텍스트 |
| 기본 UI 강조 | Inter Semi Bold | **13** | 최다 사용(152회) — 라벨·카드 제목·탭 |
| 기본 UI 본문 | Inter Regular | **13** | 108회 — 설명문 |

## 8. 카피 톤 & UX 라이팅 원칙

파일 전반에서 일관된 원칙이 관찰됩니다:

1. **AI는 판정하지 않고 제안한다** — 모든 AI 생성값에 `AI 제안` 배지. 작가가 최종 결정권자.
2. **조치의 파급 범위를 항상 명시** — "이 구절에만 적용되며 작품 전체 설정은 변경하지 않습니다", "적용 범위 안에서는 같은 차이를 반복 지적하지 않습니다".
3. **되돌릴 수 있음을 보장** — 실행 취소, 재검토, "편집 시 관련 쟁점을 다시 검토하게 됩니다".
4. **"틀림"이 아니라 "차이"** — `원작과 차이`, `확인 필요`처럼 중립적 어휘. 🔴만 `모순`.
5. 버튼은 동사형 명사구(자료 등록, 설정 확정 및 재검토), 보조 설명은 1문장 존댓말.
