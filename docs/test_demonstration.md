# Lore-Friendly — 테스트 명세 및 데모 시연 가이드 (TEST_DEMO_RUNBOOK.md)

이 문서는 밤샘 개발 중 기능 단위 테스트 체크리스트, 예외 상황 방어 검증, 그리고 내일 아침 데모 마켓(BYPP) 부스에서 진행할 3분 라이브 시연 시나리오 및 운영 매뉴얼입니다.

---

## 1. 단계별 테스트 체크리스트 (Quality Assurance)

각 개발 단계(Step) 완료 시 반드시 확인해야 하는 검증 항목입니다.

### 1.1 프론트엔드 UI & 레이아웃 테스트 (Step 1 ~ Step 3)
- [ ] **3-패널 너비 규격 고정 검증**: 좌측 `280px`, 우측 `320px`, 중앙 `flex-1` (문서 시트 최대 `720px`)이 화면 리사이징 시 찌그러지지 않는가?
- [ ] **텍스트 오버플로우 방어 검증**:
  - [ ] 우측 인스펙터 출처 아코디언(`SourceCard`) 헤더가 길어졌을 때 `truncate` 처리되어 패널 폭(320px) 밖으로 넘치지 않는가?
  - [ ] 하단 2차 보조 버튼 3개(`설정으로 확정`, `문제없음`, `보류`)의 라벨이 길어져도 2행으로 감싸지며 잘림 없이 노출되는가?
- [ ] **인라인 하이라이트 가독성**: 본문의 문제 구절에 배경색(`#FEF2F2`)과 빨간색 물결 밑줄(`wavy underline`)이 텍스트 흐름을 깨지 않고 자연스럽게 렌더링되는가?
- [ ] **모바일 반응형 최소 가드**: 화면 너비가 `1280px(xl)` 미만으로 축소되었을 때 3패널이 겹치지 않고 하단 탭(`[집필] | [검토] | [자료실]`)으로 정상 전환되는가?

### 1.2 검증 AI 및 인터랙션 테스트 (Step 3 ~ Step 4)
- [ ] **복합 앵커 치환 정확도 (Safe Replacer)**:
  - 본문 내에 `큐브`라는 단어가 여러 번 나와도 `contextPrefix`를 결합하여 의도한 구절(`붉은빛이 감도는 큐브`)만 `푸른빛이 감도는 큐브`로 정확히 치환되는가?
- [ ] **에디터 타이핑 동기화 (Dirty State)**:
  - 검증 완료 상태에서 본문을 한 글자라도 키보드로 수정(`onChange`)했을 때, 상단 인디케이터가 `재검증 필요`로 바뀌며 이전 오류 표시가 흐려지는가?
- [ ] **4대 액션 상태 머신 반영**:
  - `원고에 제안 반영` 클릭 시: 본문 교체 + 쟁점 상태 `✓ 해결됨` + 상단 미해결 카운터 즉시 감소 (`3` → `2`).
  - `문제없음` 클릭 시: 팝오버 오픈 → 라디오 사유 선택 → 해당 구절 무시 처리.
  - `보류` 클릭 시: 쟁점 상태 배지가 파란색 `보류`로 변경.
  - `작품 설정으로 확정` 클릭 시: 모달 오픈 → 승인 완료 → 상단 토스트 알림 + `localStorage`에 신규 캐넌 등록.

### 1.3 백엔드 및 장애 격리(Fail-Safe) 테스트 (Step 4)
- [ ] **정상 호출 검증**: `/api/check` 호출 시 3초 이내에 지정된 JSON 포맷(`status`, `targetQuote`, `analysis`, `suggestion`, `citation`)으로 반환되는가?
- [ ] **타임아웃 및 네트워크 차단(Offline) 방어**:
  - 노트북 Wi-Fi를 끄거나 비행기 탑승 모드로 전환한 뒤 [검증 실행]을 눌렀을 때, 크래시나 흰 화면 없이 `DEMO_FALLBACK_RESPONSE`가 0.1초 만에 로드되는가?

### 1.4 내보내기(Export) 목업 파이프라인 테스트 (Step 4)
- [ ] **미리보기 렌더링**: `export-pdf-preview`가 실제 PDF가 아닌 CSS로 A5 비율(148:210) 지면을 정상적으로 재현하는가? (`ui_ux.md §7.1`)
- [ ] **목업 진행률**: [PDF 내보내기] 클릭 시 게이지가 0 → 49%까지 애니메이션되고, 종료 직후 자동으로 다운로드가 트리거되는가?
- [ ] **샘플 PDF 다운로드**: `Lore_Friendly_Sample.pdf`가 정상적으로 저장되는가? (네트워크 오프라인 상태에서도 로컬 정적 파일이라 100% 동작해야 함)
- [ ] **Canon Index 부록 생성**: 확정된 작품 설정이 1건 이상일 때, 다운로드된 PDF 맨 뒤에 "부록 · Canon Index" 페이지가 항목 수만큼 정확히 추가되는가?
- [ ] **빈 상태 처리**: 확정된 설정이 0건일 때도 부록 페이지 없이(생략) 오류 없이 다운로드가 완료되는가?
- [ ] **따옴표 정규화**: Canon Index 항목의 변경 내용 설명에 작은따옴표(`'…'`)가 포함된 경우, 부록 페이지에는 큰따옴표(`"…"`)로 치환되어 노출되는가? (`Backend&DB.md §7.4`)

### 1.5 자료실(Library) 목업 파이프라인 테스트 (Step 4)
- [ ] **초기 상태**: 자료 0건일 때 `library-empty-state`의 "자료 추가"/"바로 집필" CTA가 정상 노출되는가?
- [ ] **목업 업로드**: 임의의 파일을 드래그앤드롭하거나 URL을 입력해 [자료 등록]을 눌렀을 때, 실제 파싱 없이 '추출 중' → 진행률 0→84% → '검토 가능'으로 정상 전환되는가? (`Backend&DB.md §8.3`)
- [ ] **자료 간 불일치 고정 노출**: 몇 건을 추가로 업로드해도 우측 메타 패널의 "자료 간 불일치" 카드가 `DEMO_INCONSISTENCIES`의 고정 1건(테서렉트 권능 범위 서술 불일치)을 그대로 보여주는가?
- [ ] **필터 칩 동작**: `전체 / 원작 자료 / 2차 정리` 필터가 `sourceType` 기준으로 목록을 정확히 걸러내는가?

## 2. 킬러 시연 시나리오 (Demo Scenario)

데모 마켓 부스를 방문한 심사위원과 참가자에게 3분 동안 보여줄 가장 직관적이고 강력한 시연 동선입니다.

### 시연 데이터 정보
* **작품명**: 《푸른 큐브의 다른 가능성》 (MCU 기반 What-If 소설)
* **챕터/장면**: 제3장 › 장면 2: 보르미르의 결정
* **갈등 상황**: 1943년 하이드라 연구소에서 레드 스컬이 손에 쥔 테서렉트의 권능을 둘러싼 모순.

---

### 3분 라이브 시연 대본 (Script & Action Flow)

```
[00:00 - 00:30] 인트로: 문제 제기 및 서비스 컨셉 소개
- 대사: "2차 창작이나 판타지 작가들이 가장 두려워하는 것이 바로 '캐붕'과 '설정 오류'입니다.
         수백 편의 원작 설정집과 이전 챕터 내용을 일일이 기억하기 어렵기 때문이죠.
         'Lore Friendly'는 글을 쓰는 즉시 세계관 충돌을 잡아내고,
         작가의 What-If 설정을 새로운 공식 캐넌으로 누적해 주는 AI 스토리 린터입니다."
- 액션: 브라우저에 Lore Friendly 메인 화면(검토 탭)을 풀스크린으로 띄움.
```

```
[00:30 - 01:20] 핵심 기능 1: 작품 내부 모순 감지 및 원클릭 교정

- 관전 포인트:
  1. 중앙 본문 시트의 "붉은빛이 감도는 큐브" 구절에 빨간색 물결 밑줄 포커싱.
  2. 우측 인스펙터에 "본 작품 제1장 장면 3 내부 설정과 충돌" 분석 및 인용문 노출.

         AI가 본문 1장 3문단의 '푸른 광채' 기록을 근거로 즉시 모순을 찾아냅니다."

             상단 카운터가 '미해결 3건'에서 '2건'으로 줄어들고 뱃지가 초록색 '✓ 해결됨'으로 바뀜.
```

```
[01:20 - 02:10] 핵심 기능 2: 원작과의 괴리(What-If) 수용 및 "작품 설정으로 확정"
- 액션 1: 좌측 패널에서 [🟡 원작과 차이: 코스믹 큐브 능력 범위 확장] 클릭.
- 관전 포인트: 본문의 "시간을 되돌리는 듯한 파동을 내뿜자" 구절 하이라이트.

         하지만 2차 창작에서는 '이게 바로 내가 쓰려는 What-If 핵심 설정'일 수 있습니다.
```

```
         테이블 앞의 QR 코드를 스캔하시면 모바일에서도 동일하게 린터를 직접 체험해보실 수 있습니다."
```

## 3. 부스 운영 비상 대응 매뉴얼 (Troubleshooting & Contingency)

현장에서 돌발 상황이 발생했을 때의 즉각 조치 가이드입니다.

| 발생 상황 | 원인 | 즉각 조치 가이드 |
|---|---|---|
| **검증 버튼 클릭 후 3초 이상 멈춤** | 행사장 Wi-Fi 지연 또는 외부 API 지연 | 이미 구현된 3초 Race 타임아웃에 의해 자동으로 `isFallback: true` 모드가 가동되어 목 데이터가 팝업되므로 당황하지 않고 시연 속행. |
| **인터넷 연결이 완전히 끊김** | 통신망 다운 | 앱의 `lib/fallbackData.ts`가 자체 내장되어 있으므로 오프라인 상태에서도 시연 동선(테서렉트 색상 교정, 설정 확정)이 100% 동작함을 확인하고 로컬(`localhost:3000`)로 시연. |
| **시연 중 브라우저 새로고침 발생** | 조작 실수 | 모든 데이터가 `localStorage`에 저장되어 있으므로 작업 중이던 원고 상태와 확정된 설정 목록이 그대로 유지됨. |
| **방문객이 스마트폰으로 접속** | 모바일 뷰 | 하단 탭바(`[집필] | [검토] | [자료실]`) 인터페이스로 자동 전환되므로 탭 전환 방식을 안내하여 체험 유도. |

## 4. 시연 전 최종 점검표 (D-15분 체크리스트)

- [ ] Vercel 프로덕션 배포 완료 및 HTTPS 정상 접속 확인
- [ ] 스마트폰 카메라로 QR 코드를 찍어 모바일 화면에서 정상 접속되는지 확인
- [ ] 브라우저 개발자 도구(F12) 콘솔에 빨간색 에러 로그가 없는지 확인
- [ ] 로컬 캐시 초기화 버튼 또는 시크릿 창(Incognito)에서 초기 상태가 깔끔하게 로드되는지 확인
- [ ] 시연 대본 3회 소리 내어 리허설 완료 (시간 2분 40초 내 도달 확인)
